🔍 CAUSA RAÍZ DEL PROBLEMA
─────────────────────────────────────────────────────────────────────────────

**DEADLOCK POR USO DE .Result EN CÓDIGO ASÍNCRONO**

En el método ActualizarPedidosAsync() (que es Async Function), se usaba:

❌ INCORRECTO (línea 1155):
    Dim resp As HttpResponseMessage = client.GetAsync(Url).Result

❌ INCORRECTO (línea 1160):
    Dim json As String = resp.Content.ReadAsStringAsync().Result

❌ INCORRECTO (línea 1190):
    Dim bodyErr = resp.Content.ReadAsStringAsync().Result

¿POR QUÉ CAUSA DEADLOCK?
─────────────────────────────────────────────────────────────────────────────
Cuando usas .Result en un método Async:

1. El hilo llama a GetAsync() y pide el resultado con .Result
2. .Result BLOQUEA el hilo actual esperando que la operación termine
3. La operación asíncrona necesita volver al MISMO hilo para completarse
4. El hilo está BLOQUEADO esperando, no puede recibir la respuesta
5. **DEADLOCK**: El hilo espera la respuesta, pero la respuesta espera el hilo

Esto es especialmente problemático en:
- Windows Forms (contexto de sincronización UI)
- ASP.NET (antes de Core)
- Cualquier código con SynchronizationContext

✅ SOLUCIÓN IMPLEMENTADA
─────────────────────────────────────────────────────────────────────────────

Reemplazar TODOS los .Result por Await con ConfigureAwait(False):

✓ CORRECTO (línea 1165):
    Dim resp As HttpResponseMessage = Await client.GetAsync(Url).ConfigureAwait(False)

✓ CORRECTO (línea 1171):
    Dim json As String = Await resp.Content.ReadAsStringAsync().ConfigureAwait(False)

✓ CORRECTO (línea 1190):
    Dim bodyErr = Await resp.Content.ReadAsStringAsync().ConfigureAwait(False)

¿POR QUÉ FUNCIONA AHORA?
─────────────────────────────────────────────────────────────────────────────
- Await NO bloquea el hilo, lo libera mientras espera la respuesta
- ConfigureAwait(False) permite que la continuación se ejecute en cualquier hilo
- No hay deadlock porque el hilo está libre para procesar otras cosas

REGLA DE ORO: NUNCA uses .Result o .Wait() en código asíncrono

❌ MAL:
    Public Async Function MiMetodo() As Task
        Dim resultado = await OtraOperacion()
        Dim data = cliente.GetAsync(url).Result  ' ❌ DEADLOCK
    End Function

✅ BIEN:
    Public Async Function MiMetodo() As Task
        Dim resultado = await OtraOperacion()
        Dim data = Await cliente.GetAsync(url).ConfigureAwait(False)  ' ✓
    End Function

¿CUÁNDO USAR ConfigureAwait(False)?
────────────────────────────────────────────────────────────────────────────
✓ En librerías y código de backend
✓ Cuando no necesitas volver al contexto original (UI thread)
✓ Para mejor rendimiento

ConfigureAwait(True) o sin ConfigureAwait:
✓ Cuando necesitas actualizar la UI después del await
✓ En event handlers de botones (pero NO en bucles dentro)

LOGGING EXTENSIVO ES CRUCIAL
────────────────────────────────────────────────────────────────────────────
Sin logging, no sabríamos dónde se quedaba colgado.
Ahora con logging detallado:
✓ Vemos cada paso de la ejecución
✓ Identificamos rápidamente dónde falla
✓ Podemos depurar en producción sin debugger
