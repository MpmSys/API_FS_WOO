📋 PROBLEMA ORIGINAL
─────────────────────────────────────────────────────────────────────────────
El programa se ejecutaba desde el Programador de Tareas pero no escribía logs.
Incluso cuando terminaba correctamente, el archivo de log estaba vacío o no
se creaba.

🔍 CAUSA RAÍZ IDENTIFICADA
─────────────────────────────────────────────────────────────────────────────
1. Los logs se acumulaban solo en memoria (StringBuilder)
2. Se escribían todos al final de la ejecución
3. Si el programa fallaba antes, se perdía toda la información
4. Las operaciones asíncronas no se esperaban correctamente

✅ SOLUCIÓN IMPLEMENTADA
─────────────────────────────────────────────────────────────────────────────

1. ESCRITURA INMEDIATA EN DISCO
   Cada llamada a EscribirLog() ahora escribe INMEDIATAMENTE en disco.

   Método utilizado: File.AppendAllText()
   - Thread-safe (lock automático)
   - Atómico (escritura completa o nada)
   - Eficiente (buffering del OS)
   - UTF-8 encoding (soporte caracteres especiales)

2. VARIABLE DE CLASE PARA RUTA DE LOG
   Se agregó LogFilePath como variable de clase para que sea accesible
   desde cualquier método.

3. CREACIÓN DE DIRECTORIO AL INICIO
   El directorio del log se crea una sola vez al inicio, con fallback
   automático al escritorio si falla.

4. REFACTORIZACIÓN ASYNC/AWAIT
   La actualización de pedidos ahora usa Await correctamente para que
   se complete antes de cerrar el programa.

5. MANEJO ROBUSTO DE ERRORES
   - Fallback automático al escritorio si falla la escritura
   - No interrumpe la ejecución del programa
   - Logging detallado de errores en Debug

  ❓ PREGUNTAS FRECUENTES
═══════════════════════════════════════════════════════════════════════════════

P: ¿El archivo de log crece indefinidamente?
R: Sí, usa File.AppendAllText. Puedes:
   - Eliminar el log manualmente entre ejecuciones
   - Usar logs con fecha en el nombre: actualizar_{fecha}.txt
   - Implementar rotación de logs (pendiente)

P: ¿Qué pasa si dos instancias escriben al mismo tiempo?
R: File.AppendAllText hace lock automático, es thread-safe.
   Las líneas pueden intercalarse pero no se corromperá el archivo.

P: ¿Afecta al rendimiento escribir línea por línea?
R: No significativamente. El OS usa buffering y la escritura es muy rápida.
   Para ~100 líneas de log, el overhead es < 10ms.

P: ¿Por qué usar AppendAllText en lugar de StreamWriter?
R: AppendAllText:
   ✓ Más simple (una sola línea)
   ✓ Thread-safe automático
   ✓ No requiere Close/Dispose
   ✓ Escritura atómica garantizada

   StreamWriter requeriría mantener un stream abierto toda la ejecución.

P: ¿Puedo desactivar la escritura inmediata?
R: Sí, simplemente no pases el parámetro /log:
   .\API_FS_WOO.exe /silent /actualizar
   (sin /log, no escribe en disco)

P: ¿El StringBuilder sigue siendo necesario?
R: Se mantiene por compatibilidad, pero ahora es redundante.
   En futuras versiones podría eliminarse.
